# План разработки Vesper Eye

Статус на 2026-09-06: P0 и базовые сценарии P1 реализованы; первый runtime-порт 0.1.0 проверен в отдельном DMS v1.6.0. Ниже сохранён полный план, а не утверждение, что все пункты завершены. Фактическое покрытие — [VALIDATION.md](VALIDATION.md).

Следующий этап: реальная пользовательская сессия без коллег, настройки экземпляра, 120 Гц/fractional scale и несколько outputs, lock/sleep, CAVA, GPU frame time. Проверять обновления DMS на candidate, без автоматического перезаписывания работающего комплекта.

## P0 — сохранить идентичность и отделить зависимости
- Исходные QML, Python, GLSL/QSB сохранены без изменения в legacy/noctalia; notices и SHA256 прилагаются.
- Разделить 1067-строчный компонент по ответственности, а не механически на куски: EyeRenderer, GazeController, BehaviorController, HostAdapter, Settings.
- Сопоставить импортируемые сервисы Noctalia с документированными свойствами DMS. Не копировать внутрь плагина старую оболочку или её notification/audio daemon.
- Создать настоящий desktop manifest только вместе с загружаемым компонентом. Указать минимальный DMS после проверки; редактор DMS отвечает за позицию/размер.

Готовность: плагин загружается в изолированном DMS, выключается и выгружается без оставшихся процессов, не зависит от qs.Commons или старых Noctalia Services.

## P1 — перенос без регрессий
- Тот же силуэт глаза и shader, реакция на указатель/локальный клик, blink/idle.
- Учесть геометрию монитора, fractional scale, перемещение и resize виджета; один корректный helper на нужную compositor instance.
- Отсутствие IPC/сервиса не должно ронять оболочку: спокойный статичный глаз + локальная диагностика без содержимого пользовательских данных.
- Закрытие DMS/плагина завершает helper. В error-path нет бесконечного быстрого restart-loop.

Готовность: baseline-сценарии проходят, исходный характер глаза сохранён. Новый визуал не маскирует функциональные ошибки порта.

## P2 — поведение и визуал
См. BEHAVIOR.md. Сначала взгляд и веки, затем радужка/свет; функциональные системные реакции — после независимой работы.

Готовность: вариативность заметна, но не отвлекает; все состояния имеют приоритеты и плавные выходы; нет постоянного напряжённого взгляда/вспышек.

## P3 — системные интеграции
- Palette adapter: Sanguine Ivory как собственный preset; возможность follow host theme.
- Notification adapter: только факт события и разрешённая категория; взгляд в сторону уведомления, cooldown. Не читать body/history ради анимации.
- Audio adapter: только по опции пользователя и только при воспроизведении; брать доступный общий spectrum сервис, не создавать второй audio capture pipeline без необходимости. Нет записи звука.
- Power/lock/DPMS adapter: снижать работу или полностью останавливать; DND/presentation/reduced-motion не дёргать глазом.
- Quick controls: спокойный режим, сон, reset position. Кнопки питания и выключение приложений через глаз не реализовывать.

## P4 — производительность и выпуск
- Замеры delta «DMS без плагина / DMS + глаз» в одинаковых сценариях. См. PERFORMANCE.md.
- Отдельно проверить 1/1.25/1.5 scale, несколько экранов, sleep/resume, отсутствие музыки/уведомлений, повторные enable/disable.
- Создать release archive из явного списка файлов, приложить checksums и список проверенных DMS/Qt/Quickshell версий.
- Сначала локальные проверки; CI и расписание обновлений добавлять отдельным согласованным изменением. Не запускать fork-код на пользовательском ПК через self-hosted runner.
- DMS и плагин обновляются независимо. Новую DMS проверять в candidate, личный release менять после проверки. Старый комплект сохраняется до успешного запуска нового.
