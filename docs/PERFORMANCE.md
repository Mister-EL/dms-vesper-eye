# Производительность: цели и метод проверки

Все числа ниже — проектные ориентиры, НЕ уже измеренные результаты. Не гарантировать затраты по одному только языку/шейдеру. Учитывать весь прирост DMS + helpers, а не только PID Python.

## Базовый принцип
Нет причины меняться — нет постоянного animation loop. Один renderer, ограниченный площадью глаза, без полноэкранных эффектов. State machine отдельно от draw. Не анимировать layout большого дерева через width/height.

## Режимы
- **Suspended:** lock/DPMS off/disabled — остановить кадровые анимации, spectrum и cursor polling. Остаются только необходимые host event subscriptions.
- **Visible resting:** нет постоянного 60 FPS «дыхания». Редкое моргание запускает короткую анимацию; курсор проверяется адаптивно, если host не даёт подходящий сигнал.
- **Active AC:** анимация синхронизирована с кадрами Qt Quick только пока есть движение; фактическая частота зависит от экрана и renderer.
- **Battery/Eco:** кадровая интерполяция без искусственного ограничения 30 FPS, реже idle-проверки, без audio-reactivity и декоративных осмотров по умолчанию.

`Item.visible` не равен отсутствию перекрытия другими окнами. Полную остановку при occlusion обещать только после проверки реального DMS/compositor API. Минимум гарантированного проектного покрытия: disable, lock, DPMS, отсутствие видимой поверхности. Не сканировать геометрию всех окон каждый кадр ради экономии.

## Реализация 0.1.1

Взгляд использует FrameAnimation только до достижения цели, без постоянного idle-loop. Входные координаты проверяются до 60 Гц при движении, после 750 мс покоя — 10 Гц Eco или 12.5 Гц обычный режим. Максимальное ожидание обнаружения нового движения из покоя около 100/80 мс плюс задержка IPC и кадра. Постоянные времени сглаживания: радужка 45 мс, зрачок 90 мс.

Eco по-прежнему отключает случайные микродвижения, осмотры и музыку, но не ухудшает частоту интерполяции взгляда. DPMS и блокировка останавливают активную анимацию; при DPMS-off нет запросов координат. Веки не меняют геометрию радужки.

Проверки 0.1.1: 13 Qt checks, 5 IPC helper tests, OpenGL 3.3 offscreen rendering and frame cadence/settling check. В основной сессии загружен размер 1400×737 на экране 120 Гц; субъективная плавность на физическом экране не измерена захватом кадров. Помощник в 15-секундном спокойном замере: около 0.13% одного CPU, 17.94 МиБ RSS. Это не полная добавочная стоимость плагина. Общий DMS RSS/CPU не выдаётся за расход глаза; прошлые замеры версии 0.1.0 не переносятся автоматически на новый размер и частоты.

## Cursor backend
Сначала проверить возможности DMS/Quickshell. Если нужен Hyprland IPC: один helper, напрямую Unix socket; не fork/exec hyprctl каждый кадр. Не предполагать, что event socket отдаёт движение мыши. Текущие интервалы fallback указаны выше; renderer интерполирует независимо. Задержку обнаружения движения в idle учитывать честно, не обещать одновременно 2 Hz polling и реакцию за 20 ms.

Выбирать текущую compositor instance по окружению/проверенному host-контексту, а не первый случайный каталог. При ошибке — bounded backoff без кручения CPU; при выключении host — helper завершается. Сетевого доступа нет.

## Ориентиры для приёмки
- Скрытый/приостановленный глаз: 0 активных кадровых циклов и 0 cursor/spectrum polling; incremental CPU стремится к нулю.
- Видимый покой: ориентир до 0.3% одного логического CPU в среднем за 60 секунд (включая редкие blink и helper).
- Активный взгляд: ориентир до 2% одного логического CPU сверх базового DMS; если не выдерживается, упростить путь или пересогласовать цель по измерениям.
- GPU: ориентир до 1 ms дополнительного frame work при выбранном размере глаза на целевом устройстве; без заметного ухудшения compositor frame pacing.
- Память: ориентир до 30 MiB дополнительного RSS всего набора процессов для первого порта, отдельный учёт GPU textures. Не считать total RSS общего DMS затратами одного плагина.
- Нет монотонного роста памяти/количества helpers после 20 enable/disable и повторных resize/theme changes.

Это критерии продукта, а не ограничение времени работы агента. Если порог не достигнут — документировать замер и исправлять, не объявлять успех по ощущениям.

## Прогон
Одинаковые разрешение, scale, refresh, питание и фоновые программы. Снять baseline DMS без глаза, затем с глазом: idle, движения, notifications burst, music on/off, resize, fullscreen, DPMS, lock/unlock, sleep/resume. Несколько повторов, отчёт median/p95 где применимо. Не смешивать влияние Windows VM/игры/локальной модели с вкладом глаза.

Проверки статические: QML syntax/imports, Python syntax и shutdown/error path, GLSL→QSB, metadata/paths, release manifest. Runtime: отдельный DMS с изолированными config/state/session bus, затем согласованный пользовательский smoke test. Сборка shader или успешный exit code не доказывают работу плагина.
