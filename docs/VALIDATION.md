# Проверка первого порта — 2026-09-06

## Среда

Arch Linux, Ryzen 7 8845H / встроенная AMD GPU; Hyprland 0.56.2, вложенный Wayland output около 1280×800 при 60 Гц. Quickshell 0.3.0 / Qt 6.11.1; DMS v1.6.0 (`0bbe83380c9406d262d567581d64477d261c9ee5`), его pinned dank-qml-common `26396ce432d6c71c3f5367438f96f4a8d667e160`. Отдельные XDG config/cache/state и D-Bus; текущая пользовательская оболочка не перезапускалась.

## Подтверждено

- Плагин загружается в реальном DMS; ShaderEffect отображается через OpenGL. В QSB добавлены нужные графические варианты.
- Центр взгляда соответствует положению desktop layer-shell окна, а не локальным координатам его поверхности.
- 12 PASS у Qt 6 runner (включая init/cleanup): удержание/отпускание, фиксированная геометрия, верхнее веко в дремоте, пробуждение, suspend-cancel, приоритет ручного ввода, cooldown, reduced motion, уведомление и возврат, ограниченный взгляд, hit area.
- 5 Python tests: нет выбора случайной compositor instance, выдача только изменённой позиции, DPMS-off без cursor requests, monitor-only режим, SIGTERM.
- 20 enable/disable: один helper на включённый экземпляр и ни одного после выключения. Это проверка жизненного цикла, **не доказательство отсутствия любых утечек памяти**.
- Настоящий nested output прошёл DPMS off/on. Синтетическое уведомление доставлено через приватный D-Bus; поведение реакции проверено в native core tests.

## Ещё не подтверждено

Физический сон/пробуждение, реальный lock/unlock пользовательской сессии, много мониторов с разным scale, primary output 120 Гц, CAVA/MPRIS с настоящим звуком, скрытие под полноэкранной игрой, GPU frame time и длительный активный cursor/motion benchmark. Код адаптеров для части этих сценариев есть, но это не замена runtime-прогону.

## Нагрузка

Первый 60-секундный замер показал около 3.46% одного логического CPU сверх DMS в покое. После остановки частого моргания в дремоте и редких осмотров — около 0.7%; поэтому для повседневной установки выбран Eco. Измерение включает процессы DMS/Quickshell/helper, но не compositor/GPU. Это вложенная сессия, не окончательный замер всего рабочего стола. RSS добавленного Python helper около 18 MiB; ранний общий прирост DMS+helper около 20 MiB. Итоговый Eco-замер: baseline ~0.17% одного CPU, DMS + глаз ~0.37%; дополнительный вклад ~0.20% и ~19 MiB RSS за 60 секунд видимого покоя. Полная активная нагрузка, compositor и GPU в эту цифру не входят; число нельзя выдавать за общий расход во всех сценариях.

Изменения Eco/tracking проверены в загруженном DMS: helper корректно получает новые параметры и остаётся в единственном экземпляре.
